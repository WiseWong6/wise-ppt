# 页面路由

本文件是 `page_kind`、14 个 `page_role` 与关系页 23 个 `relation_key` 的唯一 Markdown 权威。这里只判断页面职责和内容主关系；页面结构由完整登记骨架决定。

## 1. 先定唯一页面角色

先问“观众看完这一页，要完成什么动作？”每页只能有一个主角色。两个角色同等必要时拆页，不能任选一个，也不能用版式形状反推角色。

| `page_role` | 唯一判断标准 | `page_kind` |
|---|---|---|
| `cover` | 建立整副主题与身份，只用于开头 | nonrelationship |
| `agenda` | 预告章节或导航，不承担论证 | nonrelationship |
| `transition` | 宣告真实章节变化 | nonrelationship |
| `closing` | 收束、CTA 或致谢 | nonrelationship |
| `contact` | 联系渠道本身是页面重点 | nonrelationship |
| `hook` | 提出冲突、问题或反常识以抓注意力 | relationship |
| `orient` | 交代背景、范围或当前状态 | relationship |
| `explain` | 讲清概念、结构或机制 | relationship |
| `prove` | 用事实、数据或案例证明 claim | relationship |
| `compare` | 展示相同维度下的差异与取舍 | relationship |
| `sequence` | 顺序、阶段或路线本身是重点 | relationship |
| `act` | 明确行动、负责人或执行安排 | relationship |
| `decide` | 给出选择、推荐或拍板结论 | relationship |
| `synthesize` | 汇总前文形成总模型或总判断 | relationship |

非关系角色确定后停止，不再填写 `relation_key`。关系角色确定后，才进入第 3 节选择唯一主关系。

## 2. 角色冲突裁决

- **hook / orient / explain / prove**：制造必须继续听的张力是 hook；补齐已知背景是 orient；让观众理解“是什么、怎么运作”是 explain；让观众相信一个结论是真的才是 prove。
- **compare / decide**：差异和取舍本身是结论时是 compare；页面必须给出“选谁、做什么”的拍板结果时是 decide。推荐理由可以比较，但主角色仍是 decide。
- **sequence / act**：阶段和先后本身是重点时是 sequence；负责人、动作、期限或执行安排本身是重点时是 act。行动按时间排列不自动变成 sequence。
- **prove / synthesize**：新增事实、数据或案例来证明一个 claim 是 prove；把前文已有结论收成总模型或总判断是 synthesize。汇总页不能伪造新证据。
- **closing / contact**：收束、CTA 或致谢是 closing；联系方式、二维码或渠道本身是主要信息时是 contact。结尾位置不自动等于 closing。
- **agenda / transition**：预告整副或章节导航是 agenda；只宣告已经发生的真实章节切换是 transition。
- **orient / synthesize**：从材料外向内建立范围是 orient；从前文向上收拢已有结论是 synthesize。

若删掉任一候选角色后页面任务都会残缺，说明页面承担两个同等主任务。拆页后重新判断，不得声明“辅角色”。

## 3. 关系页先选证明方式

不要数对象，也不要先看图形。先问：观众靠什么才会相信本页 claim？

1. **靠一个主角或其结构讲清**：唯一主角是 `focus`；必须看构成或运行示意是 `illustration`。
2. **靠一组对象并排成立**：只需一起看是 `display`；强调同时推进是 `parallel`；数字本身就是结论是 `metric`；份额或资源怎样分配是 `distribution`。
3. **靠整体内部关系成立**：权级路径是 `hierarchy`；模块职责是 `decomposition`；局部对整体的位置、贡献或占比是 `part-whole`；一层包一层的边界是 `nesting`。
4. **靠方向或先后成立**：先后步骤是 `sequence`；实体沿节点移动是 `flow`；回到起点是 `cycle`；多源进入同一结果是 `convergence`；逐步筛窄是 `funnel`；回答“为什么导致”才是 `causal`。
5. **靠对象之间的差异或对应成立**：同维度看异同是 `comparison`；两条维度交叉成格子是 `matrix`；回答谁对应谁是 `mapping`；按同一指标排高低是 `ranking`。
6. **靠连接或支撑成立**：无唯一主路径的交叉连接是 `network`；集合交集是 `overlap`；多条数据、理由或案例共同支撑结论是 `evidence`。

多个对象只是同时摆在页面上、没有共同证明 claim 时，不能虚构关系。应重写 claim 或拆页。主关系只认“去掉哪个谓词后，本页 claim 就不成立”。

## 4. 关系主判定表

每行都是“主张谓词 + 排除条件”。先用 claim 找到真正必要的谓词，再确认排除条件不成立；不能按行序抢先命中。

| 族 | 中文关系 | `relation_key` | 主张成立所必需的谓词 | 排除条件 |
|---|---|---|---|---|
| 重心 | 焦点 | `focus` | 一个结论、概念或对象是唯一主角，其他内容只解释它 | 不是靠结构/场景说明运作，也不是把对象拆成独立模块 |
| 重心 | 示意 | `illustration` | 用结构或场景说明一个对象怎样构成或运作 | 不以独立模块职责、步骤、比较或容器边界为结论 |
| 并列 | 陈列 | `display` | 多个同级对象需要一起看 | 不强调同时推进、统一指标、份额或支撑结论 |
| 并列 | 并行 | `parallel` | 多条轨道、角色或工作流同时推进 | 不是单纯陈列，也没有一条主路径上的先后流动 |
| 并列 | 指标 | `metric` | 数值、单位或尺度本身直接完成论证 | 不以多个证据到结论的支撑关系或份额分配为主 |
| 并列 | 分布 | `distribution` | 份额、区间、位置或资源分配方式完成论证 | 不是按同一指标排高低，也不是整体与局部的贡献关系 |
| 包含 | 层级 | `hierarchy` | 父子、上下级、权限或层级路径完成论证 | 不只是容器边界，也不是平铺模块职责 |
| 包含 | 拆解 | `decomposition` | 一个系统被拆成可独立说明职责的模块 | 不强调局部在整体中的位置/占比，也不强调逐层容器边界 |
| 包含 | 部分整体 | `part-whole` | 同时看整体与局部，局部的位置、贡献或占比完成论证 | 不只是模块清单或份额在对象间的分配 |
| 包含 | 嵌套 | `nesting` | 一层容器包一层，内外边界完成论证 | 不以权级路径、模块职责或整体局部贡献为主 |
| 有序 | 时序 | `sequence` | 离散步骤或里程碑按时间/执行先后完成论证 | 不是优先级排名、实体流动或原因解释 |
| 有序 | 流动 | `flow` | 信息、物料、请求或状态沿节点路径移动 | 不只是事件先后，也不是多源流向一个终点 |
| 有序 | 循环 | `cycle` | 路径终点回到起点，闭环本身完成论证 | 不是有起终点的单向步骤或普通网络连接 |
| 有序 | 汇聚 | `convergence` | 多个来源沿方向共同流向一个结果 | 来源不是“证据支持结论”，且不是无方向连接 |
| 有序 | 漏斗 | `funnel` | 对象经过阶段后被筛选、收窄或减少 | 不是普通单向流动，也不是份额分布 |
| 有序 | 因果 | `causal` | 原因解释为什么导致结果 | 不只是时间上先发生或状态沿路径移动 |
| 比较 | 对比 | `comparison` | 两个及以上对象按相同维度对齐异同 | 不只是左右对象对应，也不是形成二维格子 |
| 比较 | 矩阵 | `matrix` | 两条独立维度相交形成格子或象限 | 不只是同维度比较或一组对象对应另一组对象 |
| 比较 | 映射 | `mapping` | 左右两组对象存在明确一对一或一对多对应 | 对应关系本身是结论，不以优劣异同判断为主 |
| 比较 | 排名 | `ranking` | 对象按同一指标形成高低、优先级或名次 | 顺序不是时间/执行先后，也不是流程位置 |
| 连接 | 网络 | `network` | 多节点交叉连接，没有唯一单向主路径 | 不以集合交集、包含或证据支撑为主 |
| 连接 | 交叠 | `overlap` | 集合交集或共享区域本身完成论证 | 不是一般连接或容器嵌套 |
| 连接 | 证据 | `evidence` | 多条独立证据共同支撑一个主张 | 证据不是沿路径汇入结果的流，也不是只展示多个指标 |

## 5. 关系冲突裁决

- **指标 / 证据**：一个数字本身就是结论是 metric；多条数据共同支撑另一个结论是 evidence。
- **焦点 / 示意**：一个对象是唯一主角、其他内容只解释它是 focus；必须看结构或运行机制才懂是 illustration。
- **排序 / 时序**：按重要性、得分或优先级排队是 ranking；按发生或执行时间推进是 sequence。
- **证据 / 汇聚**：理由、数据、案例在逻辑上支撑结论是 evidence；多个实体沿方向进入同一结果是 convergence。
- **因果 / 流动 / 时序**：回答“为什么导致”才是 causal；说明经过哪些节点是 flow；只说明先后是 sequence。
- **对比 / 映射 / 矩阵**：同维度看差异是 comparison；回答“谁对应谁”是 mapping；两条独立维度交叉成格子才是 matrix。
- **陈列 / 并行**：只需一起看是 display；“同时推进且互不等待”是 parallel。
- **拆解 / 部分整体 / 分布**：模块职责是 decomposition；局部对整体的位置、贡献或占比是 part-whole；多个对象之间的份额或资源分配是 distribution。内外容器边界另走 nesting。

若去掉任一候选关系，claim 都会失真，说明一页含有两个同等必要的主张。拆成两个 claim 后分别重判；不得声明“辅关系”。
