# 内容分页

本文件是制作前决定页数的唯一 Markdown 权威。页数服务于材料与讲述任务，不服务于示例、版式轮换或习惯数字。

## 1. 页数决定顺序

1. 用户明确指定页数、时长换算或逐页结构时，按该约束制作。若点名 must 无法在容量合同内放下，先说明冲突并请求取舍，不得静默删除或挤进一页。
2. 用户明确要求保留现有 deck 的页数或页序时，保持连续性；用户授权重组后才重新分页。
3. 其余任务一律内容推导：先列不可合并的 claim 和必要导航页，再得到最终页数。不存在默认页数、推荐页数或固定页数区间。

页数不使用随机数。同一份材料不会因为新聊天的 `selection_seed` 不同而增减页面；seed 只参与适配候选之间的版式排序。

## 2. 先列 claim，再数页

在判断 `page_role/relation_key` 和查询骨架前完成工作清单：

1. 写一句可被反对的 deck thesis；
2. 提取用户点名的 must、来源事实与必要结论；
3. 把材料拆成观众必须分别接受的 claim；
4. 只有两个内容共享同一观众动作、同一主角色、同一主关系且能通过同一骨架容量时才可合并；任一条件不成立就拆页；
5. cover、agenda、transition、closing、contact 只有确实承担叙事任务时才加入，不为凑页数补齐；
6. claim 与必要非关系页稳定后再计数，然后逐页进入路由和版式选择。

这份清单是制作推理，不是第二份 spec。不要为尽早得到页数而先写完整 `deck-spec.json`。

## 3. 未指定页数时

普通材料不为页数单独停下来询问。说明“按内容结构制作紧凑观点 deck”的工作假设后继续；只有不同页数会实质改变 thesis、细节深度或 must 取舍时才请求用户决定。

材料短就少做页，不用空洞页面补齐熟悉数字。材料长就拆开不可合并的主张，不得为了靠近熟悉数字而合并、删减或塞满页面。

## 4. 六页示例边界

`themes/paper-ink/examples/wise-ppt-story-six-page/` 恰好六页，只用于展示视觉质量、公开 payload 和构建合同。它的页数、页序与论证节奏都不是新任务模板；查看示例不授权复制其六页结构。

## 5. 交付自检

版式查询前确认：

- 每个候选页只有一个必须独立成立的主 claim；
- 每个 must 已计划落页，或准备登记可核对的删除理由；
- 没有为了接近六页或其他熟悉数字而合并主张；
- 没有为了接近六页或其他熟悉数字而增加封面、目录、过渡或收尾。

交付回报必须写清页数依据：用户指定时写“页数依据：用户指定，共 N 页”；内容推导时写“页数依据：内容推导，共 N 页”。
